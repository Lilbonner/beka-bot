# Деплой на Render

БЕКС — это **long-polling** бот (не веб-сервер), поэтому на Render он запускается
как **Background Worker**.

## Что нужно знать заранее

1. **Тип сервиса.** Long-polling не принимает входящий HTTP-трафик, поэтому
   бесплатный Web Service «засыпает» без запросов. Нужен **Background Worker**
   (платный план — см. `render.yaml`).
2. **Хранилище.** Файловая система Render эфемерна — SQLite-база сотрётся при
   каждом деплое. В `render.yaml` подключён **постоянный диск** (`/var/data`),
   а `DB_PATH=/var/data/beks.db`.
3. **Данные призрака.** Импортированная история (корпус ливнувшего) лежит в
   локальной базе. Коммитить её в публичный репозиторий нельзя — это чужие
   сообщения. Базу нужно засеять на диск отдельно (см. ниже).

## Шаги

1. Запушить репозиторий на GitHub (готово).
2. На <https://render.com> → **New → Blueprint** → подключить репозиторий.
   Render прочитает `render.yaml` и создаст worker с диском.
3. В настройках сервиса задать секреты окружения (помечены `sync: false`):
   - `BOT_TOKEN` — токен от @BotFather
   - `CHAT_ID` — ID целевого чата (узнать командой `/chatid`)
4. Дождаться сборки и запуска. В логах должно появиться
   `✅ Бот @… запущен. Слушаю чаты...`.

## Как засеять базу призрака на постоянный диск

База на диске Render стартует пустой. Без корпуса призрак не «оживёт» (ливнувшего
бот сам уже не соберёт). Варианты:

- **Вариант A — импорт на сервере.** Залить экспорт Telegram куда-нибудь во
  временное хранилище, открыть **Render Shell** сервиса и выполнить
  `node --disable-warning=ExperimentalWarning src/import.js <путь-к-экспорту> --only <id>`.
  Диск постоянный, поэтому импорт переживёт рестарты.
- **Вариант B — залить готовую базу.** Собрать `data/beks.db` локально и
  загрузить её на диск `/var/data/` через Render Shell.
- **Вариант C — приватный репозиторий.** Если репозиторий приватный, допустимо
  закоммитить готовую `beks.db` и копировать её на диск при первом старте.

## Альтернатива без платного worker

Можно собрать как Docker-образ (`Dockerfile`) и запустить где угодно: VPS,
Fly.io, Railway, своя машина с `docker run`. Главное — постоянный том для
`DB_PATH` и переменные `BOT_TOKEN` / `CHAT_ID`.
